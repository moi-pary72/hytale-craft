# Как владельцу лицензии безопасно импортировать Assets.zip

Текущая опубликованная beta использует только4оригинальных учебных примера и0настоящих рецептов. HySphere/OpenHytale не подключены. Эта инструкция относится к будущему разрешённому локальному review; у владельца сейчас нет игры/архива. Покупка/доступ не разрешают автоматически публичную коммерческую базу. Сначала получить разъяснение условий, включая ToS7.2 и Shared Source Agreement; см. [исследование](recipe-research/REPORT_RU.md).

1. Используйте установленную игру либо загрузчик из [официального руководства](https://support.hytale.com/hc/en-us/articles/45326769420827-Hytale-Server-Manual). OAuth device authorization проходит на официальном сайте в браузере. Пароль и refresh credentials не отправляйте в чат.
2. Сохраните Assets.zip вне репозитория. Не публикуйте игровой архив, server binaries или credentials в GitHub, публичных artifacts или общедоступном Drive. Права на игровые файлы не следуют из доступа к загрузчику.
3. Запишите точную game build с экрана установки/пакета. Не заменяйте её датой наугад. Вычислите checksum локально: `python -c "import hashlib; print(hashlib.file_digest(open('/private/Assets.zip','rb'),'sha256').hexdigest())"` (подставьте свой путь).
4. Из корня репозитория выполните:

```
python scripts/import_game_assets.py /private/Assets.zip \
  --game-version YOUR_EXACT_BUILD \
  --expected-sha256 YOUR_ARCHIVE_SHA256 \
  --output .private/assets-candidate.json \
  --report .private/assets-import-report.json
```

Каталог `.private/` исключён из Git. Команда не публикует базу и не меняет main. Если обнаружена неизвестная схема/родитель/цикл/плохой JSON — предыдущий candidate остаётся, причины в report. При неизвестных группах они сохраняются без подстановки материалов. Успешный exit означает создание кандидата, а не проверку официальной базы.

5. Сначала передайте исполнителю обезличенный отчёт с количеством и типами ошибок. Для работы с самим архивом используйте только разрешённое владельцем частное вложение/локальную среду с соблюдением условий игры. Никогда не добавляйте его в публичный PR.
6. Проверить candidate на ссылочную целостность, наследование и полную схему вашей версии; сверить представительные рецепты в игре. После разрешения на публикацию нормализованных описательных данных подготовить отдельный versioned snapshot/PR. Смешивать его с неизвестной build HySphere нельзя.

Схема, ограничения и различие candidate/source-backed/user/fixture описаны в `DATA_SCHEMA.md`. Полная корректность importer на реальном архиве пока не подтверждена.
