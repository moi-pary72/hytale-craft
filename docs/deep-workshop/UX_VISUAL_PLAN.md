# Deep workshop — visual/UX contract

## Система

Сохраняем основной художественный язык: тёмный slate/navy, тёплый кремовый текст, золото, оригинальная кузница и существующая металлическая frame.webp. Внутренние стили в отдельном deep.css и .dw-*; ни одного override главной, сцен, режимов или навигации. Никаких внешних шрифтов/трекеров, тяжёлой SPA, canvas force graph и постоянных анимаций.

Компоненты первого этапа: hero с оригинальной кузницей; inventory/item slot с frame overlay и отдельной иллюстрацией; source/status badges; summary cells; предметная карточка каталога; card actions ≥44px; disclosure-панели для заметок и paths; nested dependency cards; used-in links; стилизованные пустые/ошибочные состояния. Native details заменяет hover-only tooltip на Android и доступен клавиатурой. Badge rarity/level выводится в будущем только при наличии проверенных полей; текущие tutorial/user badges не имитируют игровые характеристики.

## Маршруты

1. Inventory → What can I craft? (также More и каталог). Главная не изменена.
2. Summary → раскрыть inventory → поиск/+/−/точный старый textarea → карточки Direct / Intermediate / All.
3. Карточка → Inspect → полноценный item detail → ингредиент → detail материала с Used in → Back.
4. Карточка → добавить в общий preview → рассчитать те же запасы совместно. Это предпросмотр, инвентарь не расходуется.
5. Detail → количество/старый Calculate/AddPlan → общие результаты и сохранённые проекты без миграции.

## Семантика discovery

Каждая независимая карточка отвечает «сколько новых предметов можно изготовить, используя весь запас». Имеющиеся экземпляры самого результата не принимаются за возможность нового крафта. Выход за batch и остатки учитывает существующий planner. Максимум в пределах999999с явной пометкой≥на верхнем лимите. Direct означает достаточные прямые ингредиенты; Chain—нужны промежуточные шаги. Оба—только материальная доступность, наличие станций не проверяется и не обещается.

Максимумы нельзя складывать. Shared preview проверяет по одному дополнительному экземпляру выбранных целей одновременно, резервируя уже имеющиеся экземпляры выбранных целей. Это конкретная стратегия с сохранением целей, не оптимизатор всех возможных производственных расписаний. Показываются нехватки/шаги/остатки. Выбор сохраняется при переходах внутри сессии, сами данные остаются в прежнем inventory storage. Повреждённые данные не перезаписываются; доступен точный редактор/backup.

## Каталог и detail

Current: поиск по переведённому имени/ID, прежняя маршрутизация целей/категорий; иллюстрированные карточки, raw-material detail, ingredients, craft path, used-in, station unknown-state, source/notes/ID, прежний calculator. Future: paginated canonical search по категориям/станциям, source/version banner, выбор альтернатив без потери group/unit/output semantics. Не приписываем текущему legacy-каталогу эти будущие возможности.

## Мобильные требования

320/360/393/430px,2слота в ряд, перенос длинных пользовательскихID, нативные tap disclosures, видимая нижняя навигация, focus/Back/Escape существующей sheet. Summary перед инвентарём; непустой inventory свёрнут до необходимости, чтобы не отодвигать доступные крафты. Reduced motion поддерживается; подсветка только при действии. Пакет оригинальных учебных WebP маленький и неизменяемый по manifest SHA256. Отдельный неизвестный пользовательский предмет получает нейтральную иллюстрацию проекта, а не вымышленный официальный арт.
