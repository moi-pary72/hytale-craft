# Real recipes: legal data plan after the 2.0 artwork release

The public build has **four original educational examples, zero verified Hytale recipes**. Their `lesson:` IDs, provenance, source selector and warnings are intentional. UI artwork does not change recipe licensing. No HySphere/OpenHytale snapshot is shipped.

1. Ask HySphere for written permission covering our exact intended use: normalized ingredients/yields/benches, public redistribution, backups, periodic updates, territories, translations and future commercial use. The draft request and current noncommercial restriction are in COMMERCIAL_DATA_READINESS.md. No automatic outreach or scraping is authorized by this plan.
2. A licensed owner may privately process their own Assets.zip with the existing importer. Keep archive, credentials and tokens private. Owning a game copy alone does not establish redistribution rights: verify the applicable game terms and obtain permission where required before publishing normalized extracts.
3. Evaluate genuinely licensed public datasets individually. Require explicit redistribution terms, item/recipe provenance, exact version, SHA-256, ingredient/output/station references, inheritance and material-group validation. Public accessibility is not a license. Never infer missing ingredients or combine incompatible versions silently.
4. Put each approved snapshot through the existing importer/unit/integration checks and an explicit publication review. Keep incomplete IDs, user recipes and learning fixtures separate. Preserve the last working snapshot and obtain a clearly documented rights decision before changing the public `user-only` policy.

Owner's next data action: obtain written permission or identify a redistributable licensed source. The artistic release proceeds independently. No ads, analytics, affiliate links or paid features are introduced.
