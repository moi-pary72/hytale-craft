# Hytale Craft — состояние для продолжения разработки

Обновлено 2026-11-14. Ветка `codex/verified-catalog-planner`. Изменения требуют просмотра PR; main и опубликованный сайт этой работой не обновляются.

## Назначение и границы

Неофициальный мобильный справочник Hytale и планировщик крафта. Приоритет — Android, настоящие игровые идентификаторы, проверяемое происхождение данных, правильный расчёт и сохранение истории. Репозиторий только https://github.com/moi-pary72/hytale-craft ; сайт https://moi-pary72.github.io/hytale-craft/ . Репозиторий `moi-pary72/moi-pary` не читать и не менять для этой задачи.

## Архитектура

Статический сайт GitHub Pages без сборки и серверной БД. `index.html` содержит исходный интерфейс, CSS и несколько изолированных скриптов: редактор, локализация, массовый расчёт, ссылки на источники, ручной импорт, диалог выбора и цели. Сохранён существующий тёмный стиль и плитки целей. `web/planner.js` содержит общий калькулятор для одиночных и массовых целей. `web/catalog.js` загружает `data/catalog.json` с того же origin; работает на Pages в подпапке.

Два разных слоя данных:

1. Общий каталог ID: `data/catalog.json`. Сейчас **3641 ID предметов, 403 ID рецептов, 0 подтверждённых рецептов с ингредиентами**. Независимый источник OpenHytale, дата генерации 2026-07-06T11:57:22.295504Z, версия игры неизвестна. Это не актуальная полная официальная база. Поля en/ru равны null: API не предоставляет названия. UI показывает оригинальный ID. Категории — эвристика по префиксу ID; это классификация интерфейса, не игровые характеристики.
2. Пользовательские рецепты: `localStorage['hytale-craft-recipes-v1']`, формат `{name:{yield,source,ingredients:{name:quantity}}}`; максимум 500. Инвентарь — `hytale-craft-inventory-v1`, язык — `hytale-craft-language`. Не переименовывать ключи без миграции. Не смешивать с подтверждённой базой. Источник, введённый пользователем, не подтверждает официальный статус.

Google Drive служит документацией и резервным хранением, не runtime API сайта.

## Карта файлов

- `index.html`: основной сайт и совместимость со старыми пользовательскими данными.
- `asset-importer.html`: отдельный старый импорт локальных JSON, ограничен явными ItemId и одним результатом.
- `web/planner.js`: рекурсия, выход за крафт, инвентарь, излишки, циклы, лимиты глубины/операций/количеств.
- `web/catalog.js`: поиск по ID, категории, карточка, RU/EN, порционное отображение.
- `scripts/sync_catalog.py`: документированные OpenHytale endpoints, проверка типов/дубликатов/размера/сокращения, атомарная запись и previous snapshot.
- `scripts/import_game_assets.py`: локальный Assets.zip, исходные ID и пути, inputs/outputs, ResourceTypeId/ItemTag, станции, SHA-256, версия. См. ограничения ниже.
- Остальные `scripts/check*`, `monitor*`, `discover*`, `probe*`: диагностические проверки источников, не импорт полной базы.
- `.github/workflows/`: пять прежних диагностических workflows, плюс validate и sync-catalog.
- `tests/test_import.py`, `tests/planner.test.js`, `tests/browser_smoke.py`: проверки на синтетических тестовых данных, не игровые рецепты.
- `docs/DATA_SOURCES.md`: реестр источников и политика продвижения.
- `docs/DEVELOPMENT_HISTORY.md`: решения и изменения.
- `docs/reports/`: отчёты; `data/source-health.json`, `data/official-downloader-status.json`, `data/recipe-discovery.json`: диагностика текущего исследования.
- `PROJECT_PASSPORT.md`, `PROJECT_DATABASE_STATUS.md`, `PRODUCT_BENCHMARK.md`: прежняя документация; при противоречии сверять код и этот документ.

## Реализовано в этой ветке

- Прекращено автоматическое заполнение новому пользователю девяти неподтверждённых исторических рецептов. Старые записи не удаляются; карточка помечает их как неподтверждённые примеры. Пользовательские данные сохранены.
- Поиск по настоящим ID и категориям, карточка с датой/источником и явным отсутствием подтверждённого рецепта. Цели оружия/брони/инструментов/еды/строительства/станций открывают соответствующий каталог.
- Выбор локального рецепта сразу показывает ингредиенты, выход и статус пользовательского рецепта, без пустого поиска. После сохранения редактор тоже показывает карточку.
- Общий калькулятор одиночных и массовых целей. Излишек выдаётся после расчёта ингредиентов: рецепт A -> A с выходом 2 больше не маскируется излишком. Инвентарь, выход партиями, переиспользование излишков, недостача, список добычи и копирование сохранены. Старый список очищается перед новым неуспешным расчётом.
- Безопасный повторяемый импорт ID, отчёт, защита от пустой/резко сократившейся базы, предыдущая версия при изменении. Сбой сети не меняет опубликованный JSON.
- Ежедневное обновление ID готовит PR, не пишет в main. Нужны разрешённые repository workflow permissions для создания PR; при запрете останется artifact и ошибка, автоматического merge нет.
- Усилен локальный импорт Assets.zip: версия обязательна в CLI, SHA-256, список предметов, дубликаты ID, unresolved references, явная неподдерживаемая наследуемость, предотвращение подстановки implicit output вместо испорченного явного output, атомарная запись/резервная копия.

## Что НЕ готово

**Assets.zip не получен, 0 подтверждённых полных рецептов.** Официальный загрузчик доступен, но игровые архивы требуют OAuth. Не запускались авторизация и загрузка игры. Секретов нет.

Локальный импортёр консервативен: не разрешает Parent/inheritance, не разрешает группы ресурсов/теги до конкретного предмета; не готов для полного игрового архива. Сохраняет группы как группы и помечает возможность расчёта; CLI не заменяет рабочий файл при отклонённых assets. Несколько outputs, альтернативные рецепты, станции и локализации пока не подключены к общему калькулятору. Полный нормализованный asset-файл не загружается сайтом автоматически. Не утверждать обратное.

Официальные имена RU/EN и игровые характеристики в ID API отсутствуют. Не выводить человекочитаемое предположение как настоящее название. Источники разных версий нельзя смешивать. Все 3641 ID включают служебные/template ID — API не сообщает, что доступно игроку.

Сохраняется технический долг монолитного index.html, частичный перевод старых динамических сообщений, старые ручные JSON-импортёры требуют дальнейшей унификации с Python и проверки наследования. Навигация неподготовленных игровых разделов честно сообщает об отсутствии содержимого.

## Безопасный следующий этап

1. Владелец лицензии получает архив через официальный downloader у себя: OAuth device flow в браузере; refresh credentials хранить вне репозитория и публичных artifacts. Можно использовать локальную установленную игру. Не передавать пароль в чат. Игровой архив не публиковать в GitHub или публичном Drive.
2. На разрешённом архиве изучить настоящую схему, реализовать Parent с циклами, локализации, standalone/embedded recipes, ресурсы и теги, multiple output и альтернативы. Тестировать на реальных обезличенных минимальных фрагментах, если их публикация допустима.
3. Кандидат импорта создавать отдельно от production: `python scripts/import_game_assets.py /private/Assets.zip --game-version REAL_BUILD --output /private/candidate.json`. Сейчас ожидаем отказ на Parent; это честная блокировка, не успех.
4. Проверить ссылочную целостность, репрезентативные рецепты по независимому источнику той же версии, станции и выход; затем отдельным PR подключить рецептный snapshot к UI. Не использовать ID-only catalog как рецептную базу.
5. Просмотреть этот PR и разрешить merge отдельно. После merge проверить Pages на Android. Нет разрешения на merge в этой сессии.
