## Extraction tools are not dataset licences

A new practical tool check found [KyuubiSoft `/ksdev` exports](https://wiki.kyuubisoft.com/hytale/dev-tools/): authorized server admin commands export item/block/entity lists into local JSON, require dev.admin. **Recipes are not listed among documented export fields**, so this is not evidence of a full recipe exporter or free commercial recipe feed. Plugin licence/pricing/output redistribution scope are not established here. No plugin/server downloaded or run. [Hytems MIT](https://github.com/lushbit/Hytems/blob/master/LICENSE) also licenses its viewer code, not a separately approved vanilla dump. Our own stdlib/JS tools avoid these dependencies and costs.

## Concrete recommendation

Continue releasing our own engine and original learning content now. Keep real-data publication blocked independently of technical success. While waiting for the already-sent studio answer, prepare an evaluation specification for ModLabs:20–50explicitly authorized records covering fixed/group input, different units, alternatives, co-products, salvage, benches/tiers/unlocks; exact build/channel plus provenance and permitted caching/advertising/browser/Git redistribution/update terms. Sending that supplier request still requires owner authorization; none was sent.

After studio guidance, prefer an independently generated canonical snapshot from authorized files, using the small verified sample as regression evidence. A permissively licensed mod collection may be a separately labelled optional source, but cannot be presented as vanilla Hytale or silently substitute for it. No currently checked route supplies thousands of verified commercially redistributable recipes to our public build today.
