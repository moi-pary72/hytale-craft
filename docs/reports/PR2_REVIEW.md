## Найдено и исправлено

- Каталог был только ID, карточка находилась после длинного списка. Теперь source-backed snapshot отдельно, карточка перед списком и scroll/focus непосредственно в неё.
- Не было действий при missing recipe. Добавлена кнопка пользовательского редактора с предзаполненным оригинальным ID; source-backed данные не перезаписываются.
- Поиск только ID. Теперь English name/ID, плюс поисковая фраза пользователя для Crude Shortbow; псевдоним не публикуется как официальный перевод.
- Метаданные дат нельзя хардкодить для будущих обновлений. Selector берёт timestamp из самого набора; разные источники/версии разделены.
- Source-backed рецепты, инвентарь, stations и массовый план теперь подключены к общему engine через отдельный version-isolated adapter. Планы сохраняются по source revision.
- Неверный/отрицательный stock отклоняется. Плохое сохранение пользовательского рецепта не объявляется успешным; код откатывает изменение в памяти.
- Parent и плохой explicit Output в старых браузерных импортёрах не должны маскироваться implicit fallback. Такие импорты теперь отклоняются; сложные архивы — через Python candidate importer.
- Настоящие цепочки конверсий содержат циклы. Без явного выбора «получить отдельно» расчёт останавливается, вместо бесконечной рекурсии или выдуманного raw material.
- Новая база проверяется SHA-256 в браузере; неверный хеш приводит к ID-only fallback с сообщением. Проверка воспроизведена route injection в integration test.
- Добавлен browser smoke в GitHub CI. ID workflow не создаёт PR из-за одного обновившегося timestamp отчёта при неизменившемся каталоге.
